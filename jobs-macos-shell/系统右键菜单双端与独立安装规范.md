## 🔥 <span id="前言">前言</span>

> 本附件是系统右键功能的平台范围、独立工程与管理面板主规则。命中系统右键菜单或 `OS@Extension` 功能任务时必须读取；入口布局与 README 按 [OS@Extension 脚本布局](../jobs-markdown-docs/README规范-OS@Extension脚本布局.md)执行。

## 一、<span id="feature-contract">双端功能与安装边界</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

1、系统右键功能默认同时覆盖 [**macOS**](https://www.apple.com/macos/) 与 [**Windows**](https://www.microsoft.com/windows)。新增或修改功能时同时核对两端实现、管理清单、文档和验证；截图来自一端、当前运行环境只能验证一端，都不能自动把任务缩为单端。

2、用户明确指出的单端要求优先。先从当前对话与已确认项目约束识别例外，再决定需要实现的平台；不能为机械对齐重复增加系统已有且用户明确排除的入口。

3、每个功能使用独立子工程，具有自己的业务源码、功能标识、安装 / 卸载状态和管理入口，能够独立安装与卸载。完整功能目录可整体复制管理，共用基础设施不能携带其它功能业务，单个聚合开关不能冒充独立子工程。

4、两端各自提供管理面板，并同时包含安装 / 更新与卸载功能；平台总面板只管理本端功能集合。macOS 面板不安装或卸载 Windows 功能，Windows 面板不管理 macOS 功能；同一功能的单项入口仅管理本项。面板开发与验收统一执行[安装卸载管理面板基准](./安装卸载管理面板基准.md)。

5、管理面板默认空选，支持单项或多项操作；任务开始前取消、关闭或空选不启动安装 / 卸载，主操作按钮为本轮最终确认。已开始的任务按基准执行关闭驻留保护，不能将关窗等同于中断任务。保留 `.command` / `.cmd` 公开入口及独立包能力，入口只唤起本端 GUI 并结束启动任务，已有工作终端会话保留。

6、交付前逐项核对“面板选项 → 功能 ID → 独立工程 → 菜单 / 宿主业务 → 安装产物与状态”，补齐上级入口和就近 README。两端隔离验证、真实安装及菜单交互分别报告；一端构建通过不能代表另一端已验收，普通测试不执行真实注册、卸载或重启文件管理器。

7、右键菜单涉及 SDK 下载、安装及首次调用补齐组件时，必须执行[SDK 环境先决条件与持续自动获取](./SKILL.md#sdk-acquisition-retry)：默认自动重试至就绪或用户主动结束，不再要求下载／重试确认；同时核对独立入口、聚合同包及平台组件，不能只修 Flutter 运行这一处。

8、macOS 安装成功须在事务提交、旧副本／本轮构建产物处理及最终刷新之后，核对精确安装路径的 FinderSync 登记并有界观察稳定性；短暂出现一次“已启用”不能作为最终成功。删除事务旧 App 前按精确宿主／扩展路径注销，保留其它位置和未选模块；登记丢失只修复本轮目标，路径身份改变、查询失败或取消须停止并如实报告。多项安装共享观察窗口，保留进度，不逐项叠加等待；隔离覆盖延迟撤销、修复失败、取消及其它模块保全，实际菜单显示另验。

## 二、<span id="mac-file-create-exception">单端例外：新建文件</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

用户明确要求 macOS 增加“新建文件”，Windows 已由系统自带、无需再加时，只在 `OS@Extension/MacOS@Extension/JobsFileCreator` 实现独立功能 `file-create`，接入 macOS 管理面板。Windows 保留系统“新建”，不创建对应扩展；此例外只限定该功能，不改变其它系统右键任务的双端默认范围。

## 三、<span id="clean-menu-symmetry">clean 终端版与双端右键版联动</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

用户确认 `clean` 原终端入口与磁盘右键清理是对称维护的独立实现。以下路径以 `JobsGenesis` 根目录为基准，仅用于开发定位，不能写成运行时依赖：

| 入口 | 自维护源码 |
| --- | --- |
| 原 macOS 终端 `clean` | `JobsConfigOS/🌍JobsMacEnvVarConfigs/scripts/【MacOS】clean.command/【MacOS】clean.command` |
| macOS 右键清理 | `OS@Extension/MacOS@Extension/JobsDiskSpaceInfo/Scripts/【MacOS】清理磁盘空间.command/【MacOS】清理磁盘空间.command` |
| WindowsOS 右键清理 | `OS@Extension/WindowsOS@Extension/JobsDiskSpaceInfo/Scripts/Clean.ps1/Clean.ps1` |
| 功能、差异与验证对照 | `OS@Extension/项目相关报告/磁盘空间信息资产盘点.md` |

- 任一入口发生清理功能、范围、默认值、保护措施或失败处理变化时，先核对三处实现；原终端 `clean` 新增、删除或调整功能，必须在同一任务同步两端右键清理代码、就近 README、内置自述及功能对照表，不等待用户再次提醒。
- 每个清理入口都携带本平台完整代码，不运行时 `source`／导入／转调原 `clean`、另一平台或其它仓库，不用外部软链接及构建时临时复制原脚本冒充独立实现。各自包内的启动器与业务脚本可以按相对路径协作。
- 按行为和保护边界对齐，不强求不同语言逐字相同。平台专属能力提供可核实的本地等价项；确无对应能力或系统 API 受限时，在功能对照表明确差异与原因，不静默漏项、不伪造支持。仅菜单运输、宿主通信等右键专用变化可以只改对应入口，但仍核对其没有改变清理语义。
- Cleaner for Xcode 对应的开发清理阶段先于既有 `clean` 步骤执行。进入前先询问：回车继续、任意非空输入加回车跳过；只有选择继续才扫描、统计和整理清理候选。按 Device Support、Simulators、SwiftUI Previews、DerivedData、Archives、Caches 分组，每组 fzf 第一行及默认焦点必须是“清理当前组全部”，下面列真实子项，支持单选／多选；默认焦点不等于自动删除。必选菜单按[空格确认规则](./SKILL.md#fzf-required-selection)处理零勾选的当前项，仍展示最终准确范围、经本组确认后才清理；取消、无有效选择及失败不自动视为全部。跳过／未选项不得被后续通用清理绕过，Windows 按适用能力明确映射和不适用项，不伪造 Xcode 支持。
- 同步后验证本轮受影响的两端候选筛选、确认／取消、链接或重解析点、备份失败、并发变化、失败退出和发布包自包含性；使用隔离夹具，不为验收直接清理用户真实缓存、历史或模拟器。源码验证、目标系统执行、实际安装菜单分别记录。更新代码不授权安装、提权、真实清理、提交或推送。
