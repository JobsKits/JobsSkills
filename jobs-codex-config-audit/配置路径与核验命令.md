## 🔥 <span id="前言">前言</span>

## 一、<span id="config-sources">标准源与运行位置</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 全局指导标准源：

  ```text
  /Users/jobs/Documents/Github/JobsGenesis/JobsConfigOS/💻JobsCodexConfigs
  └── AGENTS.md
  ```

- 用户级 Skills 运行态、标准源与现行基准工作树：`/Users/jobs/.agents/skills/`。
- 用户级 Skills 备份态：`/Users/jobs/Documents/Github/JobsGenesis/JobsConfigOS/💻JobsCodexConfigs/skills/`，同时是父仓的 `JobsSkills` 子模块工作区。
- 全局 `AGENTS.md` 运行态目标：`/Users/jobs/.codex/AGENTS.md`。
- Skills 工作树的远端必须是 `https://github.com/JobsKits/JobsSkills`。`JobsCodexConfigs/skills` 只是 `JobsSkills` 子模块挂载，父仓只跟踪 `.gitmodules` 和 gitlink；不得把子模块或历史备份反向覆盖现行基准工作树，也不得把 [**Obsidian**](https://obsidian.md) Vault 整体拷进 Skill。

## 二、<span id="workspace-checks">工作区只读检查</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

审计开始先执行以下检查，保留两个仓库已有改动：

```shell
git -C /Users/jobs/Documents/Github/JobsGenesis/JobsConfigOS/💻JobsCodexConfigs status --short
git -C /Users/jobs/Documents/Github/JobsGenesis/JobsConfigOS/💻JobsCodexConfigs diff -- AGENTS.md
git -C /Users/jobs/.agents/skills status --short
git -C /Users/jobs/.agents/skills diff
```

## 三、<span id="validation-commands">规则校验与差异检查</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

在现行 Skills 工作树根目录运行；校验其它 Skill 时将参数替换为其实际目录：

```shell
python3 /Users/jobs/.codex/skills/.system/skill-creator/scripts/quick_validate.py ./jobs-codex-config-audit
zsh -n ./jobs-codex-config-audit/scripts/audit_codex_configs.zsh
zsh ./jobs-codex-config-audit/scripts/audit_codex_configs.zsh
```

再检查两个仓库的差异，并人工核对规则的触发、动作、边界、例外、验证与归属均有承载：

```shell
git -C /Users/jobs/.agents/skills diff --check
git -C /Users/jobs/.agents/skills diff
git -C /Users/jobs/Documents/Github/JobsGenesis/JobsConfigOS/💻JobsCodexConfigs diff --check
git -C /Users/jobs/Documents/Github/JobsGenesis/JobsConfigOS/💻JobsCodexConfigs diff -- AGENTS.md .gitmodules skills
```

## 四、<span id="deployment-checks">即时备份与部署核验</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 触发：每次写入运行态 Skills 后，立即按相同相对路径同步本次变更到备份态，包括新增 / 修改的 `SKILL.md`、同级附件、references、脚本、模板、资源和配套说明；无需再次确认，不等待任务结束、Git 提交、推送或用户提醒。
- 写入前比较源与目标，保留可核对的原文或快照和已有改动。备份有有效独有内容时先合并；无法安全合并时保留双方并报告具体冲突，不静默覆盖或反向覆盖运行态。
- 只同步本次变更，不复制 `.git`、内置 Skills、插件缓存，不做全目录镜像删除，不清理目标独有 / 无关文件；删除仅传播本任务明确授权的对应删除。同步前检查软链接，不写穿外援上游，沿用现有所有权与 Git 排除边界。
- 写入后逐文件 `cmp` 或内容哈希验证一致；失败时报告具体文件和原因，不把未完成的复制标为成功。新增文件确认已落到相同相对路径，获准删除则核对两态对应项均不存在。

在 `JobsCodexConfigs` 标准源根目录运行：

```shell
cmp ./AGENTS.md /Users/jobs/.codex/AGENTS.md
cmp /Users/jobs/.agents/skills/jobs-codex-config-audit/SKILL.md ./skills/jobs-codex-config-audit/SKILL.md
cmp /Users/jobs/.agents/skills/jobs-codex-config-audit/配置路径与核验命令.md ./skills/jobs-codex-config-audit/配置路径与核验命令.md
git -C /Users/jobs/.agents/skills remote get-url origin
git -C /Users/jobs/Documents/Github/JobsGenesis/JobsConfigOS/💻JobsCodexConfigs submodule status -- skills
```

上述 Skills 文件仅为本 Skill 的核验示例，实际任务逐项替换为本次变更清单。备份子模块 HEAD 可以暂时落后于运行态，但本次变更的工作区文件必须即时同步；显式报告两者提交号，不以 gitlink 状态代替文件内容一致性。不得用落后的子模块反向覆盖现行基准；本地核验与同步不代表获准 [**Git**](https://git-scm.com/) 提交、推送或父仓 gitlink 更新，获准版本发布时仍先子仓后父仓。
