## 🔥 <span id="前言">前言</span>

> [主规范](./SKILL.md)要求命中原生或平台差异时读取相关部分。这里只列影响判断的核验点，不固定各工程的版本、runner、测试数量或实现方案；版本以本次配置和官方资料为准。

## <span id="jobs-toc-heading-2" data-jobs-toc="v2">一、跨平台共有边界 <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a></span><!-- jobs-toc:heading-end -->

- 以实际 shell 和运行时执行，核对参数引用、空格／中文／特殊字符路径、工作目录、大小写敏感、换行、执行位和符号链接。源文件编码、文件读写编码、终端代码页和进程 stdin／stdout／stderr 协议分别核对；一个 UTF-8 设置不能证明整条链正确。
- 所需命令、SDK、系统组件、服务与端点明确准备，缓存只作加速，不能成为冷启动成功的前提。无缓存 runner 的依赖索引来源应按实际安装成本和锁文件语义确定；小文件 GET 或 `git ls-remote` 成功／更快不证明完整大仓库可在预算内克隆。存在已验证的官方轻量索引及现有显式选源入口时，可仅在 CI 进程固定来源，验证适配器保持版本／校验和／私源和严格部署约束，再用真实冷安装验收；不能仅加长超时或改变本机全局选源。凭据／外设／GUI 会话缺失时标明边界，不把假命令、假设备或编译通过写成真实操作验收。
- 子进程失败、预期非零、取消、超时、断管道和清理须保留原始结果；只回收本次拥有的进程和资源，恢复确实改动的环境，不能以清理覆盖原始异常。归档夹具使用正确的成员路径、字节和元数据，不修改安全校验去接受错误夹具。
- 修改复用 workflow、复合 action 或共享执行器时核对调用者的参数、secret、权限、输出及制品契约；矩阵变量、包名与路径须在各维度成立。

## <span id="jobs-toc-heading-3" data-jobs-toc="v2">二、[**Windows**](https://learn.microsoft.com/windows/) 与 [**PowerShell**](https://learn.microsoft.com/powershell/) <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a></span><!-- jobs-toc:heading-end -->

- `powershell` 与 `pwsh` 是不同执行目标；Windows PowerShell 5.1／.NET Framework 与 PowerShell 7／现代 .NET 的语法、API、编码及子进程行为不能互相代验。按实际目标解析并运行，涉及旧引擎时核对非 ASCII 源码的编码／BOM。
- Actions 内置 PowerShell 包装包含错误偏好及末尾 `$LASTEXITCODE` 检查，参照 [官方 shell 语义](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepsshell)。负向原生命令可留下非零状态；验证测试进程本身的退出码及聚合器逐项失败传递，不用统一重置状态掩盖失败。
- 原生命令管道、CMD／OEM、TTY 交互和中文路径分别验证真实字节与结果。交互工具不能仅用无 TTY mock 验收；环境变量“缺失／空值／有值”、父子进程环境隔离和恢复按目标运行时核验。
- Win32、窗口控件／字体尺寸、注册表、文件身份、桌面会话与架构相关测试须有真实目标证据；托管 runner 非交互测试不证明 Explorer 菜单、ARM 桌面或真实 SDK／设备业务通过。平台条件跳过须出现在交付说明中。

## <span id="jobs-toc-heading-4" data-jobs-toc="v2">三、[**Linux**](https://www.kernel.org/) 与 [**MacOS**](https://www.apple.com/macos/) <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a></span><!-- jobs-toc:heading-end -->

- 不以本机默认 shell 代替配置中的 `bash`／`sh`／`zsh`；自定义 shell 参数也会改变失败传播。核对管道与日志工具后的退出码、可执行位、大小写和系统工具参数差异。
- GNU／BSD 工具、系统库、动态库路径及包管理器位置按 runner 实际情况处理，不依赖个人登录配置或交互式初始化。无图形会话、权限或硬件时不冒称桌面／设备验收。
- [**Xcode**](https://developer.apple.com/xcode)／Apple SDK、目标架构、模拟器运行时、签名与制品导出分别核对。更换 runner 镜像或 Xcode 主版本时，同时对账官方镜像清单、`runs-on`、显式开发者目录变量、应用目录匹配、实际版本断言和同主版本模拟器选择；不能只改 runner 标签而保留旧工具链选择。对 workflow 中实际执行的选择代码验证当前主版本成功、旧主版本拒绝和探测命令失败传递，再保留真实目标环境证据；命令夹具不等于托管 runner 已验收。构建／模拟器通过不外推真机、签名发布或商店交付。涉及前台／时序的测试失败时，核对真实Scene状态、宿主初始化差异及实屏权限窗口；保持二进制和断言不变做有界环境对照，只处理本任务应用并恢复设置，不把弹窗造成的inactive直接归为业务缺陷。证书等敏感信息仅使用现有授权机制，不写入日志或仓库。

- 同提交 App 制品的实屏身份须覆盖实际代码载体。Debug App 若使用独立 `.debug.dylib`，主可执行文件可能只是启动 stub；同时核对主文件和代码 dylib 的平台／架构及安装前后 SHA，不能只凭 stub 相同认领代码一致。整包以官方 artifact 摘要校验，资源与运行验证继续绑定同一提交。

- 第三方源码因新 Apple SDK 的私有头边界失败时，先核对首错与 SDK 公开入口说明。受源码所有权限制时，可在自有、精确 target 配置中使用转发到公开入口的兼容头。先从锁版官方原文清点所有同类直接消费者及实际 target 设置；本机 Pods 可能已有补丁，零匹配不能证明上游无问题。只把经真实编译证明需要适配的 target 纳入精确名单，宿主共用头放中性构建支持目录并纳入源码指纹，避免逐个冷 CI 才暴露同类入口或让无关包装库相互依赖。锁定上游原文并以同目标 SDK、真实 target 的参数／PCH／头映射及模块／警告设置编译完整生产文件，补相关类型和宏可用验证。搜索路径中的兼容头也可能截获 SDK 内部包含并形成循环；以独立空模块缓存验证原始失败、当前失败和修复后冷／热构建，核对实际生成的系统模块，再区分 SDK 自身构建与外部消费者的合法入口。不能以热缓存或缺少生产上下文的探针成功代替此验证，不能修改第三方文件或全局关闭模块／诊断。

- CocoaPods 工程已有主工程测试 target 时，核对真实 Podfile 的测试声明及安装器去集成行为；源 pbx 中已有的 Pods base xcconfig 不等于安装后仍保留。按实际依赖关系声明测试搜索路径继承，并在依赖安装后、昂贵测试宿主构建前校验测试配置和真实 PCH／扫描命令。PCH对照须记录是否经过实际构建服务的依赖扫描、工具采用的会话／模块缓存路径及已有产品复用；传入缓存参数不等于被采纳，冷态以实际路径和初始目录证明，不能用热模块或直接编译耗时代替冷构建上界。单独调用依赖配置生成器时，复现已有安装后的必要规范化并保留原始／处理后摘要；核有效架构没有被排空及预期编译／产物确实发生，空动作的退出0不算通过。PCH还消费App自有库时，仅Pods继承不足；按同配置合并必要的显式头／framework／library搜索字段，保留Tests原值、路径引号／变量／顺序和inherited，不整份复制链接、签名或产品设置。门禁须独立拒绝显式覆盖丢失inherited或App必要搜索上下文，未定义字段仍允许正常继承。保留无依赖安装的 audit-only 合同，不以 App 自身构建成功代替测试 target，也不逐个补供应商头路径或关闭 PCH 绕过缺失上下文。
- Rust 多架构源码缓存、Xcode 测试专用 DerivedData／Intermediates、主工程 Products 与最终 ZIP 分别登记生命周期。可将源码构建缓存限定到本次 runner 临时目录，但清理前须证明导出的 framework／头／模型不再依赖该缓存；测试专用目录只能在实际用例与签名审计完成后回收。主 App 构建继续需要的 Products 不随测试中间产物清理，已声明归档的 resp／hmap／VFS、原始 xcresult 和日志须先保全；修改清理路径时同时核对上传清单、来源守卫及后续真实目标构建，不能只用空目录夹具声称空间问题已解决。

- 验证 Swift 消费者时保留文件级导入边界，分别编译完整源文件或以真实模块的独立编译单元检查；不能把多份消费者拼成单个文件后声称导入正确，另一文件的 import 会掩盖缺失依赖。命中未声明模块符号时，补显式导入，并用仅删除该导入的独立负向源复现原错误；同 SDK 的真实依赖及 Actor／桥接头设置不能被接口桩取代。
