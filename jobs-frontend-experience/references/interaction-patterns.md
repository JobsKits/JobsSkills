## 🔥 <span id="前言">前言</span>

> 这是可组合的共通交互与移动端契约；App 经验只在标明的载体适用。桌面 Web 及移动 Web 的浏览器约束另见[Web 独立表现模式](./web-patterns.md)。按当前功能的用户任务选择模式；行业归类给出起点，实际角色、内容与操作风险决定采用哪些模式。下列经验默认项不等于所有 App 都要具备的功能清单。

## 一、<span id="shell-and-navigation">移动端外壳与共通账户边界</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

以下外壳默认针对手机 App；移动 Web 仅在任务适合时借鉴，桌面 Web 不套用此表的 Tab、首页／我的排列。账户身份、全局设置与任务恢复仍为共通要求。

| 决策 | 手机 App 的默认采用 | 改用其它模式的条件 |
| --- | --- | --- |
| 手机主布局 | 竖向阅读、单手可达的主要操作，兼容安全区及键盘 | 视频、图表、创作等任务按需横屏；不因默认竖排直接锁死系统旋转 |
| 顶层导航 | 有 3～5 个独立、常用目的地时采用底部 Tab，上图下文并标明选中态 | 只有一个流程时保留流程导航；不要凑 Tab 或把“提交／支付／发布”伪装成目的地 |
| 首个 Tab | 综合业务可用“首页”组织发现与分发 | IM 可直接进会话，交易可直接进行情／资产，学习可进学习任务；不强插运营首页 |
| 最后一个 Tab | 有账户体系且个人业务足够时使用“我的”，容纳资料、个人记录与设置 | 轻量功能可将账户与设置归入口菜单，不为“我的”制造无效页 |
| 账户设置 | 有账户时提供资料、适用的账户安全及退出入口；全局语言与主题始终可达 | 不把访客可用的全局设置藏在必须登录后才能进入的页面 |

- 原生 App 的 Tab 切换保留各自导航栈、筛选及列表位置；返回从详情回到来源上下文，不无条件回首页。角标表达真正待处理信息，不常驻伪红点。
- **登录、注册、忘记密码是一道完整的门，三条路径必须一起可达。** 可以同页切换或分别路由，但登录界面不能缺注册与找回入口；注册／找回成功后有明确的登录去向，错误、取消、返回和再次发送验证都能恢复。受控后台的账号开通可进入其既定管理员开通／申请流程，不为满足入口擅自开放管理员自注册；不能用无效按钮冒充已提供流程。
- 允许游客浏览的首页不因未登录被整页拦截；游客可见登录／注册入口，点击依赖账户的功能时才进入上述门。登录成功后重新请求当前页及账户相关数据、刷新身份显示；按原任务恢复上下文，不让用户手动刷新才能看到登录结果。
- **已登录时，用用户头像与用户名替换原登录／注册入口。** 账户菜单及“我的订单”等私有入口随会话状态出现；退出、会话失效或切换账号后同步还原游客入口，并清理上一账号的私有内容。
- **正式环境后台必须登录后才能使用。** 初始进入、深链、刷新与会话过期均先验证身份，再加载受保护页面和数据；服务端继续校验角色与权限，不能靠隐藏导航或前端状态代替鉴权。
- **Demo 后台是明确例外：免登录直接进入，演示用户名统一为 `admin`、密码为 `1234`。** 仅在明确的 Demo 构建／运行配置下启用，自动建立独立演示身份并清楚标明演示状态；这些凭据只用于样例，不配置成正式环境账号、默认密码或可写真实数据的后门。服务故障、超时或鉴权失败不能自动开启后台免登录；切回正式环境时重新校验真实会话，隔离演示与真实数据。
- “我的”未登录可选择显示访客版，或在打开个人私有内容时进入登录；选择取决于该页是否有可公开浏览的价值。依赖 UID 的写入与私有数据必须鉴权，界面隐藏不能代替服务端授权。
- 登录拦截保存来源路由、必要参数与未提交输入；登录成功回到原任务。支付、删除、发布等有副作用动作重新呈现确认，不因登录完成自动提交；取消登录返回原页面。
- 按钮是否图文结合取决于识别收益：高频明确动作可纯文字，空间受限且含义稳定的图标可单独呈现并具备无障碍名称；不能给每个按钮强配图标。
- **设置入口默认用齿轮图标。** App、移动 Web 与桌面 Web 的独立设置按钮优先复用项目图标体系的齿轮，不直接以“设置”二字充当按钮主体；保留本地化无障碍名称、足够点击区域及可见焦点，桌面可补悬停提示。设置页标题、菜单中的设置条目及导航体系已有的图文标签仍按上下文表达，不机械去掉全部文字。
- **同一界面的全局设置入口通常只出现一次，默认收口个人中心／账户菜单。** 没有个人中心或游客也需切换语言、主题时，可以在全局顶栏保留一个入口；用户明确指定位置时沿用指定方案，不在首页主区、登录按钮下及顶栏重复摆放。
- 服务地址、请求超时等连接调试设置只在 Demo 中展示；正式产品设置保留面向用户的项目，连接参数由部署／运行配置管理。
- 账户与后台验收覆盖游客浏览及登录拦截、三条门路径、登录后资料替换与数据刷新、退出／过期、正式后台未登录的深链／刷新，以及明确 Demo 的免登录。检查正常服务、离线和鉴权失败，确保后两者不会绕过正式权限；设置入口不重复、调试字段仅在 Demo 可见。

### 1.1、<span id="persistent-selection">按钮、Tab 与导航的持续选中态</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- App、移动 Web、桌面 Web 与小程序中，用按钮、Tab、导航项或可选卡片表达当前目的地、筛选或选择时，选中与未选中必须有明确、持续的视觉差异；不能仅实现悬停或按下瞬间的 `:active`。一次性提交、刷新等普通动作不伪造持续选中状态。
- **背景、主标题、副标题与图标一起响应状态。** 选中项使用与未选中项明显不同的背景填充及标题／副标题文字颜色，存在图标时同步其前景色；沿用项目语义 Token，分别定义明暗主题下的两态。副标题保持次级层次及可读对比，不能沿用旧灰色导致落在选中背景上看不清。字体、字重、尺寸或标识可辅助区分，但不能只靠字重、细边框或很浅的颜色差别提示选中。
- 视觉状态与真实选择一致，同步按钮和子内容，不让父按钮已选中而标题／副标题仍使用未选中色。Web 按控件语义选用 `aria-pressed`、`aria-selected` 或 `aria-current`，原生端使用等价状态；不把三种属性叠加到每个按钮。键盘焦点单独清晰可见，悬停、聚焦、失焦及主题切换不清除当前选择。
- 验收点击与键盘切换、旧项取消选中、鼠标移开及焦点转移，核对所选内容与状态一致；分别查看明暗主题中选中／未选中项的背景、主副标题和图标对比，以及长语言、字体放大后的排布。移动触控端无悬停也能直接辨认当前项。

### 1.2、<span id="dropdown-control-layout">下拉选择控件的箭头、留白与尺度</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **正文与箭头分区，箭头不贴边。** 常见左到右布局中，箭头距右边框保留舒适留白并在垂直方向对齐；正文末端单独预留箭头宽度、图文间距及边缘留白，长文案、长翻译与字体放大后也不覆盖箭头。其它阅读方向按控件实际布局处理，不能只增加正文内边距却让箭头仍贴着边框。
- 高度、宽度及上下／左右内边距随字号、内容、同排控件和页面密度协调；筛选栏可紧凑，表单与触控场景保留必要操作空间。不要为修复箭头留白把所有选择器一律做高、做宽，也不为显得紧凑而压缩可用点击区域；不跨端规定同一套像素尺寸或外观。
- Web 原生箭头的位置不受正文 `padding` 可靠控制时，优先沿用项目已有、经目标浏览器验证的方案；需要装饰箭头时仍保留原生 `select`，为正文独立留区，避免原生与装饰箭头重叠。装饰层不拦截点击、不另造焦点；原生 App 与小程序依据平台选择组件和项目设计系统处理，不照搬 Web 的外观重置。
- 明暗及跟随系统主题中，分别核对正文、箭头、背景与边框的可读性，以及悬停、可见键盘焦点和禁用状态；调整外观不能消掉焦点提示，也不能让禁用箭头与背景混成一片。选择、展开及禁用继续服从组件真实状态，不只改视觉样式。
- 保留标签关联、读屏名称、键盘打开／选择／关闭、表单取值及原生禁用语义；不能为移动箭头把成熟选择控件降成只响应鼠标的容器。自定义菜单触发器沿用其既有可访问交互，不冒充原生选择器。
- 验收最窄支持宽度、最长有效选项／翻译、字体放大、明暗主题及上述状态，实际检查箭头两侧留白、文字不遮挡和同排尺度；再用键盘完成一次选择并核对真实值。源码里的 `padding` 数值或单张默认态截图不能代替这些结果。

## 二、<span id="carousel">运营轮播的零张、一张与多张</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 仅在有精选内容或运营分发任务时设置轮播位；核心任务必须能从稳定入口到达，不能只存在于某一帧轮播。
- 已选用轮播位但接口缺失、失败或没有有效卡片时，展示至少一张有意义的打包兜底资源；业务明确关闭该运营位时隐藏，不用兜底图对抗关闭配置。根本没有分发任务时不新增轮播。
- 一张有效卡片静态展示，不启用定时器、循环手势或伪分页点；多张且未另指定时默认无限循环，末项后回到首项，并支持分页、手势和可配置自动轮播；减少动态效果等情境可退为手动。默认向下一项推进，常见中文／英文布局表现为右向左；方向受平台、阅读方向和明确设计约束。
- **普通内容轮播不呈现播放器控件。** App、移动 Web 与桌面 Web 均保留自动滚动和人工干预，但页面不显式摆放“开启／播放／暂停／继续”按钮，也不以播放三角或暂停图标替代这些按钮。手动切换可用滑动、分页标识及按布局需要保留的前后箭头；此规则不移除真实音视频播放器自身的媒体控制。
- **用分页标识表达位置，不显式显示“当前页／总页数”。** 默认当前项为实心点，其余项为空心点，不能全部实心只靠颜色深浅区分。标识可点击切换时具备清楚的本地化无障碍名称和选中状态；读屏可以保留“第几项／共几项”语义，不能把数字计数重新渲染到页面上。
- **自定义标识必须有两种可辨认的状态。** 当前项与非当前项的形状、填充、轮廓、尺寸等表现应明显不同，不拘泥于圆点，也不能只靠颜色变化；例如体育内容可用足球／篮球表示当前项，其余项用空心轮廓或另一套明确的弱化样式。优先沿用品牌及项目图标体系，新增素材仍按全局来源与本地打包规则处理。
- 自动间隔可配置，并保证文案可读。手动拖动／点击切换时暂停或重置计时，允许自动恢复的触控场景须从完整间隔重新计时，不能刚切完就被定时器抢回。只有可见、前台且未被用户明确停止时才按约定恢复；离屏、切 Tab、进入后台和销毁时停止计时，恢复时保持单一计时源。
- Web 悬停或聚焦轮播内容时停止自动推进，键盘聚焦触发的停止不因移开焦点就擅自恢复；支持键盘切换、读屏选中态与减少动态效果设置，循环副本不能制造重复焦点。需要无障碍停止／恢复能力时采用平台辅助动作或可发现的键盘机制，不重新加入页面上的播放器按钮。上述隐藏视觉控件是 Jobs 的产品约定；[**W3C** 轮播教程](https://www.w3.org/WAI/tutorials/carousels/)与[轮播交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/)还包含显式轮转控制要求，不能仅据本约定声称完整符合其模式。
- 验收至少覆盖零／一／多张、自动推进、末项回首项、滑动／点击／键盘切换、人工干预后的计时、前后台与焦点、深浅主题；截图确认没有播放控制或数字页码，当前与其余标识确有两种样式。
- 卡片使用稳定 ID、图片／替代说明、可选文案和受约束目标。内部目标进入已登记功能页；外部 HTTPS 目标按约定在外部浏览器或受控浏览容器打开；无效、已下线或无权限目标给出可恢复反馈，不白屏或崩溃。兜底图无有效目标时不可伪装成可点击。

## 三、<span id="lists-and-refresh">列表、刷新与连续性</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

| 数据语义 | 交互契约 |
| --- | --- |
| 发现流、商品流等可持续增长列表 | 移动 App 可下拉刷新、触底／上拉追加；移动 Web 仅在不冲突浏览器手势时采用，并保留显式刷新／加载入口。桌面 Web 按连续浏览或精确检索选择“加载更多”／分页／更新按钮，不默认下拉刷新；均明确加载中、失败重试与没有更多 |
| IM 会话消息 | 向上加载历史并保持视觉锚点；新消息追加，用户在底部才跟随滚动，查看历史时提示新消息数量 |
| 有限设置项、表单、静态详情 | 不机械增加上下拉；更新入口跟随任务需要 |
| 桌面检索、订单管理或需精确定位记录 | 可用分页、筛选和明确刷新按钮，避免无限滚动吞掉页脚和位置感 |

- 刷新、分页、筛选切换共享明确请求归属；去重并忽略失效请求结果。刷新失败保留已有内容，不把整页清空；局部加载失败放在对应区域，不用全局空态覆盖有效数据。
- 返回列表恢复滚动、筛选和已选对象；切换账户清理上一账户私有缓存。提交中防重复操作，失败保留输入；允许撤销的动作优先提供撤销。

## 四、<span id="states-and-feedback">图片、空态与反馈分层</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 网络图先显示打包 Logo 或语义相符的本地资源，固定容器比例防止跳动，再异步替换；失败保留兜底。商品、头像、封面分别选裁剪规则，不能用同一张装饰图冒充不同实体。
- 素材执行全局 iconfont 优先与可追溯本地打包规则；用户指定素材优先。骨架屏是等待状态，不是无数据或失败状态；不以长时间假加载掩盖不可用服务。

| 状态 | 页面表达与下一步 |
| --- | --- |
| 初次无数据 | 语义图形、简短原因及当前可做动作，例如开始首条记录；动态列表保留重新加载入口 |
| 搜索／筛选无结果 | 保留搜索词及条件，提供改词、清除条件或重新加载 |
| 请求失败／离线 | 显示可理解原因和重试；有旧内容保留并标明更新失败 |
| 未登录／权限不足 | 区分登录可解决与无权访问，分别给登录或返回／申请权限入口 |
| 数据下架／记录删除 | 说明资源不可用并返回来源，不误写“网络异常” |

- 空态采用全局一致的插画／图标、标题、说明及操作结构，按原因换语义；iOS 优先复用 JobsEmptyAuto，其它端复用项目等价控件。
- 自动消失的 Toast／短提示只承载不需要记忆和决策的轻反馈；网络失败、表单错误、支付结果等需要处理的信息在对应页面持续可见。
- 需用户选择、确认风险或明确下一步时才用对话框／底部面板；文案写清动作及后果，关闭方式明确。弹层能否点遮罩关闭按是否会丢输入及任务风险决定；不把所有反馈升级成确认弹窗。

## 五、<span id="payments">支付入口与结果可信性</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 当前功能包含支付且面向中国大陆普通商品／线下服务时，支付方案默认同时考虑支付宝与微信支付。先核验商品类型、目标渠道、宿主能力、商户已开通资质及接口配置，再决定可用项；不将经验写成“所有地区、所有 App 都只允许这两种”。
- iOS 应用内数字内容、会员与功能解锁先核验当前 App Store 规则及适用例外；实物和线下消费服务另作判断。不能直接套普通商品收银台，也不能因客户端能唤起支付就认定具备上线条件。[Apple 审核指南 3.1](https://developer.apple.com/app-store/review/guidelines/#payments)是动态核验入口。
- 收银台呈现订单摘要、金额与币种、费用明细及实际可用方式；服务端有支付有效期时展示并处理到期。优惠、地址、开票、分期等仅在本期业务需要时增加；不为完整模板发明促销规则。
- 业务订单、支付尝试、退款分别有状态；同一业务订单可能有多次支付尝试，不能以一个“已完成”字段混合。客户端跳回仅表示流程返回，以服务端确认查询结果，等待确认时显示“支付结果确认中”，保留查询与返回入口。
- 覆盖取消、失败、超时、处理中与成功；本期支持退款时再覆盖退款中及退款结果；未知结果先查询原支付，禁止直接诱导再次付款。返回订单保留上下文，服务端返回的权威状态优先。
- API 优先、本地演示回退执行全局规则，但演示记录与真实账户／订单隔离，显著标识“演示／未实际扣款”；真实提交结果未知时不能回退成“模拟支付成功”，不能自动补发演示操作到生产。

核验日期：2026-11-05；轮播、导航与支付的平台规则在实际项目采用时重新核验。

## 六、<span id="adaptive-composition">Web、手机与大屏的同义重组</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 先区分 App 与浏览器宿主，再按可用空间和输入能力设计；完整 Web 导航、内容组织及响应式策略必须读取[Web 独立表现模式](./web-patterns.md)。共同保留角色、内容语义、主任务和业务状态；手机常用单列逐层进入，宽屏按业务使用顶栏／侧栏、多列或列表详情并列。不能把 Web 处理成 App 的拉宽版，也不把桌面表格整体缩小塞进手机。
- 原生端采用平台导航栈、返回及手势；Web 保持可分享 URL、刷新／深链可达、浏览器前进后退与可见焦点。触摸端不依赖 hover，桌面不依赖手势作为唯一入口。
- 主操作在安全区、键盘和文本放大后仍可达；长标题、空字符串、超大金额、长列表和媒体不同比例都要进入预览样例。正文与表单不要为视觉整齐强行截断关键含义。
- 全局三主题与十语言是基础契约；样式以语义 Token 绑定文本、背景、强调、状态与间距。检查长翻译、藏文字体／行高、数字币种与时区表达，主题切换不能破坏层次及对比。
- 页面跳转、卡片反馈和状态变化用动效解释因果；短反馈不阻塞后续输入。减少动态效果时保留状态可辨识性，不用重复弹跳、闪烁和无意义轮播制造“活泼”。
