## 🔥 <span id="前言">前言</span>

> 本附件由[业务体验主规范](../SKILL.md)按需加载。下面是从任务出发的设计经验归纳，不是严谨的行业分类、收入模型分类或市场审美定律。复用稳定的信息顺序、决策条件和交互骨架，再围绕用户本期选中的功能组合页面。

## 一、<span id="select-pattern">选择与组合模式</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

行业标签只缩小候选范围；广告、抽佣、订阅等收入方式不能直接推出样式。先确定“用户反复完成什么”，再结合内容形态、角色、风险和使用情境选择模式。

| 任务模式 | 核心价值循环 | 优先表达 |
| --- | --- | --- |
| 资金与交易决策 | 看资产／行情→判断→操作→核对 | 金额、时点、条件、风险与结果 |
| 内容消费与发现 | 看见→消费→反馈→继续发现 | 作品、阅读节奏、连续消费 |
| 关系与社区 | 发现人／话题→建立关系→表达→收到回应 | 身份、关系、讨论上下文 |
| 即时通信 | 进入会话→收发→确认状态→继续交流 | 消息、未读位置、输入与送达 |
| 商品交易 | 发现→比较→选规格→购买→售后 | 商品证据、价格、条件与购买 |
| 服务预约与履约 | 提需求→匹配／报价→预约→履行→确认 | 时间、地点、范围、责任与进度 |
| 学习与订阅内容 | 发现→确认权益→消费→积累进度→继续 | 目录、权益、进度、继续入口 |
| 多角色业务流程 | 接收→处理→交接→确认完成 | 待办、归属、阶段与下一步 |

- 先选一条主线，辅助能力只服务该主线。例如商品客服复用即时通信，不因此增加通讯录；内容付费复用交易，不因此增加完整商城。
- 以下“最少页面组合”描述逻辑职责，可以落在页面、抽屉或弹层中，不是必须逐个新建页面。只采用用户选中功能成立所必需的部分。
- 跨行业共用的状态、导航、图片和支付交互由[交互默认](./interaction-patterns.md)维护；这里仅列会改变该类页面判断的差异。

判断所需页面时，再检查两种修饰条件：

- **角色与阶段：** 访客、已有用户、买家、卖家、服务方可以共享信息模型，首屏优先级和可执行动作按当前任务变化；不默认增加用户没有要求的交付端。
- **使用情境：** 先区分 App、移动 Web、桌面 Web；Web 必须再读[独立表现模式](./web-patterns.md)。窄屏重连续推进，宽屏可并列比较或呈现列表详情；同业务不代表相同页面外壳。高频复用优先缩短路径，低频高风险操作优先解释条件与确认结果。

## 二、<span id="finance">资金与交易决策</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 资产／行情概览、对象详情、操作确认、结果／记录；只做查行情时停在详情，不自动补开户、充值或交易。
- **首屏构图：** 金额／价格是主信息，紧邻币种、单位、时间和变化口径；趋势服务判断，主操作与促销入口分层。资产隐私与遮罩按需求保留。
- **状态不变量：** 展示报价、待确认金额与最终成交事实不能混淆；失效报价、请求处理中、失败和状态未知有不同解释。超时不能直接判失败并诱导重复交易。
- **常见误用：** 用装饰图表代替决策信息；把演示收益当真实收益；用红绿颜色作为唯一涨跌证据；把“可信”固化为全站低表现力，或按国籍预设审美。

金融属于高风险决策场景，信任首先来自信息准确、边界清楚和结果可核对。品牌发现区与资金确认区可以有不同视觉力度。

## 三、<span id="content">内容消费与发现</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 内容入口、消费详情、用户选中的反馈结果／记录；仅做收藏时可补收藏列表，未选评论与发布就不加创作中心。
- **首屏构图：** 根据内容选阅读列表、图片网格或沉浸视频；标题、封面、作者和时长的排序取决于消费决策。作品应占主导，外围操作退让。
- **状态不变量：** 返回恢复阅读／播放位置和列表上下文；内容删除、不可访问与加载失败分别处理；点赞／收藏失败可恢复，反馈不打断主要消费。
- **常见误用：** 将所有内容统一成同尺寸卡片；新闻长文套短视频全屏模式；为了“活泼”叠加持续动画；案例有推荐流就默认开发推荐算法。

阅读靠可扫描的信息与排版节奏，图片发现靠作品比例和视觉密度，视频消费靠沉浸、播放状态与手势连续性；三者不能仅更换素材。

## 四、<span id="community">关系与社区</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 人／话题／社区入口、内容或身份详情、所选互动与结果；选中发布时补编辑、草稿保留与发布反馈。
- **首屏构图：** 身份、关系与内容共同建立语境；作者、话题和互动区域清楚对应。主要行动取决于当前任务是加入、关注、发布还是回复。
- **状态不变量：** 关注、加入、申请中与已加入不能合并；评论回复保留对象及上下文；隐私、删除或受限内容有清楚解释，发布失败保留输入。
- **常见误用：** 用互动数字堆出“社交感”；把浏览内容强制改为登录／关注；仅借鉴发布功能却自动加入好友、群组、私信和社区治理后台。

社交关系是用户之间的持续连接，内容分发是发现与消费；二者可以组合，但选中一个不能默认获得另一个的需求授权。

## 五、<span id="messaging">即时通信</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 会话入口、聊天页、所选消息类型的发送／预览；单客服或直达会话可以省略独立会话列表。图片、音视频和文件仅按本期范围加入。
- **首屏构图：** 会话列表突出对象、最近消息、时间与未读；聊天页让消息序列成为主角，输入区适应键盘与安全区，媒体保持可理解的比例和状态。
- **状态不变量：** 待发送、发送中、失败与服务端确认分开；送达／已读仅在真实支持时显示。加载历史保持阅读锚点，新消息不强行打断正在回看的用户。
- **常见误用：** 把消息持久化统一归为高级功能；用本地追加冒充跨用户送达；重试产生重复消息；自动滚到底覆盖未读定位；未选通讯录却增好友体系。

历史存储、跨端同步、离线恢复与检索应逐项说明支持范围。保留历史是否必要取决于交流任务，不能把“聊天界面能显示消息”当作完整即时通信能力。

## 六、<span id="commerce">商品交易</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 商品入口、详情与规格确认、购买确认、订单详情，有支付时增加支付选择与结果；只做展示则不补交易。单商品可直购，虚拟商品不强加地址和物流，多商品合并购买才判断是否需要购物车。
- **首屏构图：** 商品证据与购买条件优先：主图／效果、标题、当前规格、实际价格结构、可售状态、权益及主动作；促销标签不能掩盖最终支付金额和适用限制。
- **状态不变量：** 业务订单、支付单、售后单、退款单分别表达。付款成功不等于交付完成，申请售后不等于退款成功；一单多支付尝试或部分退款时仍能解释对应关系。
- **常见误用：** 把电商等同“大促首页＋购物车”；向买卖双方显示两套冲突事实；从客户端支付返回直接认定成交；把库存、优惠门槛和售后政策按案例擅自补成业务规则。

同一订单事实按角色投影文案和可执行动作：买方“待收货”与卖方“待买家收货”共享同一履约阶段。本期支持部分交付、部分售后或部分退款时，才显示涉及的商品／数量／金额，而非用一个总状态覆盖所有明细。

## 七、<span id="service">服务预约与履约</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 需求／服务详情、条件选择与报价／预约确认、履约详情及结果；只有业务确需派单、抢单或报价时才加入相应入口，不因存在双端就自动建设完整平台。
- **首屏构图：** 当前任务所需的时间、地点、服务范围、价格依据和可用性优先；进行中页面突出当前阶段、负责方及下一步。地点可以是文字，不默认引入地图。
- **状态不变量：** 提交需求、有人接单、预约成立和服务完成互不等价；双方对同一事实看到各自责任。时间冲突、无人响应、取消与争议需要相应恢复路径。
- **常见误用：** 把服务当作有库存的实物商品；只有付款结果而无履约过程；未确认就设计自动接单、违约罚款、取消时限或评价规则。

12306 的核心任务包含班次、乘客、席位与时间约束；货运包含运力、路线、装卸与履约。它们可共用交易机制，但不能直接复用服装商城的规格与物流页面。

## 八、<span id="learning">学习与订阅内容</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 内容／课程入口、目录与权益详情、学习／播放页、继续入口与进度；免费内容无需付费页，单次购买与订阅按真实业务区分。
- **首屏构图：** 未开始时表达内容价值、适用对象与结构；已开始时优先“继续学习”和当前进度；详情将可试看、已拥有、需购买部分清楚区分。
- **状态不变量：** 播放位置、完成进度与权益状态独立；付费失败不能授予真实权益，权益到期不能悄然删除学习记录。中断后的恢复与跨端支持按实际能力表达。
- **常见误用：** 所有学习产品都加签到、积分和排行榜；用订单“已支付”代替权益激活；进度只做视觉百分比而不能续学；未选考试就建设题库考试系统。

此模式关注持续消费与积累，不把所有教育业务归为内容订阅；预约辅导可采用服务履约，公开资料阅读可仅采用内容消费。

## 九、<span id="workflow">多角色业务流程</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- **最少页面组合：** 与当前角色有关的待办／记录、任务详情、处理确认及结果；必要时有交接／补充资料。仅查询报表时不补审批系统或完整管理端。
- **首屏构图：** 待处理事项、优先级、截止条件与归属优先；表格适合比较，卡片适合独立任务，详情组织事实、处理依据与动作。确有决策用途才加统计图表。
- **状态不变量：** 业务阶段、处理人、权限与下一步动作一致；处理中、已提交、已受理和已完成分开。并发更新、权限变化和补充资料后不能继续展示旧动作。
- **常见误用：** 自动生成“仪表盘＋CRUD菜单”；每项任务都套步骤条；忽略交接和处理中断；把运营／商户能力全部塞进消费者的“我的”。

需要固定顺序的流程表达当前步骤；可以自由顺序、分多次完成的任务才考虑任务清单与各项状态，避免仅因业务复杂就创建长向导。
